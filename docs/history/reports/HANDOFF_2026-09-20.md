## 4. How this repository is different, and why it will refuse your commit

The documentation is gated like code. A tool called **docsync**
(`scripts/doc_state_sync.py`) parses the documents, cross-checks declared
facts, and fails a commit when they contradict each other. It is not
decoration: it exists because this project is built across many short
sessions, and a document that quietly went stale costs more than a failing
test.

Things that will surprise you:

- **`--fix` before `--check`.** Write your log entry first, then run
  `scripts/doc_state_sync.py --fix`, which rewrites the machine-managed
  blocks. Only then does `--check` pass.
- **A commit that touches the control plane is refused with exit 3.** That is
  `scripts/docsync/`, `scripts/doc_state_sync.py`,
  `scripts/dev/docsync_preflight.py` and `.docsync.toml`. The one sanctioned
  escape is `SKIP=doc-state-sync-check git commit`, and only after running
  `scripts/doc_state_sync.py --check` yourself and seeing exit 0.
  **`--no-verify` is forbidden, without exception.**
- **The branch is not yours to choose.** A guard fails any commit on a branch
  `PLAYBOOK.md` Section 3 does not name, with code WT003. Changing the branch
  is the owner's decision.
- **Phrases in Section 3 do mechanical work.** "Batch N is complete", "Batch
  N is not yet defined" and "WP-N is next" are parsed. They must sit on one
  line: the parser reads Section 3 line by line, and a sentence wrapped
  across two lines matches nothing. This cost one debugging cycle on
  2026-09-20.
- **The test count cannot be typed in.** It is parsed out of the dated log
  entries and cross-checked in three places. To change it, write a dated
  entry whose validation line carries `**N passed**` in bold, then run
  `--fix`. `F-DOCSYNC-13` explains why and proposes a better mechanism.
- **Never add `Co-authored-by` trailers.** The owner manages attribution.

## 5. The operational fact most likely to bite you

**Check that the database schema has actually been migrated.** On 2026-09-20
the live database still held the pre-Batch-22 schema, and had done since the
batch shipped. Nothing failed, because every cache read is wrapped and
degrades to a cache-less run -- so 3,628 usable rows went unread on every
search and every MusicBrainz correction was bought at one request per second
and then discarded.

```
# with DATABASE_URL set in the shell -- init_db.py does not read .env
<python> init_db.py
```

It is idempotent and safe to re-run. On Fly.io it runs automatically as the
release command; **locally, nothing runs it for you.**

Since that day, the code says so itself: a cache read that hits SQLSTATE
42703 or 42P01 logs a line naming `init_db.py`, because a missing column
never heals and a dropped connection always does, and reporting them the same
way is what let this hide. If you see that line, run the initializer.

## 6. What Batch 23 is

A Spotify listener uploads the **Extended Streaming History** export they can
request from their own account, and gets the same album rankings and heatmap
a Last.fm user gets. No Spotify login -- the API cannot supply lifetime
history and development-mode apps are capped at five users, so the owner
rejected that path. The upload is parsed in memory and discarded; nothing is
written to disk or the database.

Eight work packages, WP-0 through WP-7, are specified with acceptance
criteria in `BATCH23_DEFINITION.md`. The task-level detail, with commands and
test lists, is in
`docs/superpowers/plans/2026-09-13-batch23-spotify-export-import.md`.

**WP-7 carries an obligation from two batches ago:** a frontend and
accessibility audit that was deferred so it would run once over the final
interface. The batch does not close until it has run.

To open the batch: name its branch in `PLAYBOOK.md` Section 3, replace the
"Batch 23 is not yet defined" sentence with an active-batch declaration
naming `BATCH23_DEFINITION.md`, and create that branch. It must not be
`test`.

## 8. If you change the frontend

Run `scripts/dev/frontend_gate.py`. It serves the real application and drives
Chromium and Firefox through 30 checks. It is slow and it is the only thing
that catches layout regressions.

One warning, learned expensively on 2026-09-20: **a contrast number from that
gate is a measurement to reproduce, not a verdict.** Its colour parser read
the first three numbers of any computed colour as 0-255 channels, but a CSS
`color-mix()` surface serializes as `color(srgb 0.96 0.94 0.91)` with
channels in 0-1. It produced three false failures in a row, and two design
changes made to satisfy them had to be reverted. The parser now refuses a
serialization it cannot read rather than guessing -- but the lesson
generalizes to every automated finding in this repository. Reproduce it
before you act on it.
