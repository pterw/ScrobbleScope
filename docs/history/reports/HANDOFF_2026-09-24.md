CI (`.github/workflows/test.yml`) runs the same installs on Linux. No `.env`
and no Postgres are needed for the suite or the gates. Three things a cloud
sandbox does differently, all met in the first cloud session:

- **The Tailwind download fails** in the `tailwind-css-drift` hook: Python
  3.13's strict certificate checks reject the sandbox proxy's CA ("CA cert
  does not include key usage extension"). Fetch the three pinned artifacts
  with `curl` into `scripts/bin/` (gitignored); `tailwind_build.py` checks
  each against its pinned SHA-256 on every run, so verification is not
  weakened. The URLs and hashes are `required_artifacts()` in
  `scripts/dev/tailwind_build.py`.
- **The frontend gate cannot run.** The pinned Playwright wants browser
  builds the sandbox does not ship, and the sandbox forbids
  `playwright install`. Only foundation Task 8 touches the gate's paths:
  run that task's frontend gate locally or rely on CI's `quality-gate`, and
  say which in its Section 4 entry.
- **Codacy's API is blocked** by the egress policy. When its check fails,
  ask the owner for the rule and line from the Codacy UI.

**The guard fails against `origin/main` since PR #241:** WT006 ("behind")
while the branch has no commits past the merge, WT005 ("diverged") once it
does. `main` holds the branch's commits plus its own older history under
different SHAs, so `git diff $(git merge-base HEAD origin/main) origin/main`
is empty -- `HANDOFF_PROMPT.md`'s expected WT005 case. Run the guard with
`--base-ref origin/test`, as above; WT000 there is the pass.

## 4. How the work is run

Subagent-driven development: one fresh implementer per task, then an
independent review and an independent gate run, then fix rounds until clean.

- **Workspace.** Create `.superpowers/sdd/<date>-batch23-wp0-foundation-cloud/`.
  Copy `.superpowers/cloud-kit/constraints.md` into it as `constraints.md`,
  and keep a `progress.md` ledger there: one line per dispatch, result,
  review verdict, gate result and ruling.
- **Agents.** Dispatch the general-purpose agent, prompt opening "Follow
  `.superpowers/cloud-kit/agents/<name>.md` as your instructions.", with the
  inputs that file lists:
  - `sdd-implementer` (sonnet): WORKSPACE, BRIEF, REPORT, BASE, plus a context
    file for anything the brief cannot know (pre-flight facts, owner
    rulings). Resume the same implementer for fix rounds.
  - `sdd-reviewer` (sonnet): BRIEF, REPORT, DIFF, WORKSPACE, REVIEW path.
    Always add: never edit the working tree (Lesson L9); sweep the whole
    task range for stale copies of every fact the task changed (L12); check
    the plan checkboxes and count sites (L11).
  - `gate-runner` (haiku): WORKSPACE, REPO, BASE, LOG_DIR. Check LOG_DIR holds
    a log per gate, and that every code its summary quotes is in a log,
    before recording its verdict (L10, L13).
  - `sweeper` (haiku): TERMS, with `REGEX: yes` and `\b` for ids such as
    `F-B21-6\b`. Spot-check "no other hits" with one `git grep -c -P`.
  - **Never dispatch Opus.** Sonnet for implementers and reviewers, haiku for
    gate-runner and sweeper (owner cost policy).
- **Briefs and review packages** without the plugin scripts:

  ```bash
  # Brief: the task's section of the plan, up to the next heading or rule.
  awk '/^### Task 6:/{f=1;print;next} f&&(/^### Task /||/^## /||/^---$/){exit} f' \
    docs/superpowers/plans/2026-09-21-batch23-wp0-foundation.md > "$WS/task-6-brief.md"
  # Review package: commits, stat and the net diff for BASE..HEAD.
  { git log --oneline BASE..HEAD; git diff --stat BASE..HEAD; git diff -U10 BASE..HEAD; } \
    > "$WS/review-BASE..HEAD.diff"
  ```
- **One writer at a time.** No implementer runs while another agent writes, and
  the controller writes tracked files only when nobody holds the pen. A
  reviewer and a gate-runner may run side by side; neither writes.
- **Before recording anything, verify it.** Re-read the claim at source, or
  run the command. A subagent's summary is not evidence (Lessons L9-L10, L13).
- **Pushing.** Hold a task's commits until its review is recorded clean, then
  push with the owner's go. The stop hook asks to push after every turn;
  decline it until then.
