Problem

The plan distributes the privacy and memory guarantee across request creation, synchronous inspection, thread hand-off and asynchronous parsing.

Deepen

Give export reading one explicit resource lifecycle, with caller-visible ownership transfer and cleanup responsibility for rejection and successful hand-off.

Deletion test

Remove callers' need to coordinate zip handles and stream positions. Preserve the synchronous directory check and incremental parsing inside that lifecycle.

Tests through the interface

Cover invalid directory, admission refusal, thread-start failure, parser failure and success; show resources close and private data never escapes.

  • locality: resource ownership is explicit
  • leverage: both export modes share it
  • privacy tested across the hand-off
Design refinement, not a new framework. Do not move Flask or job knowledge into the parser. Preserve the request-level cap before CSRF, the separate job-admission module, the parse semaphore, source-specific rules and process-and-discard policy. A semaphore limits active parsing; it does not alone bound buffers waiting for a permit. The planned concurrent-upload measurement remains essential.
Evidence and timing

WP-2 specifies directory validation and streamed limits; WP-3 specifies parsing, buffer closure and a two-parser semaphore; WP-4 specifies request buffering, synchronous rejection and thread dispatch. The older detailed plan constructs BytesIO(data) at dispatch; this is plan evidence, not implemented behavior.

When: settle ownership during WP-2 to WP-4 design. Prefer keeping it within the approved modules; amend the plan if it changes responsibility or acceptance. No current leak or OOM is asserted.
