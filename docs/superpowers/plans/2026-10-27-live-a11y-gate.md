# Live Accessibility Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Test the live app in Chromium for what no gate sees today: axe-core WCAG 2.x A/AA on every migrated page, a generic keyboard tab-through, and a real click through `static/js/page-motion.js`; and make the workflow log name every live check it runs.

**Architecture:** Three new checks live in three new `_frontend_gate_*` modules, registered in `CHECKS` as one new group that runs on Chromium only. A fourth new module holds the page states the axe and keyboard checks share (seeded jobs, the existing interaction states). axe-core is a pinned, hash-verified vendored file under `scripts/dev/vendor/axe-core/`; known violations sit in an explicit baseline that fails when it goes stale. The gate prints one line per enabled check.

**Tech Stack:** Python 3.13, Playwright 1.62.0 (sync API, Chromium), axe-core 4.14.0 (MPL-2.0), pytest 9.0.3.

**This plan holds behaviour, frozen interfaces and acceptance checks, not implementation code** (owner standing rule, 2026-10-24). Each implementer writes the tests and the code; a short snippet appears only where a selector, a regex or an exact string is itself the interface.

## Global Constraints

- **Chromium only. Firefox is not covered.** The owner browses in Firefox; the owner asked for Chromium for these checks. `BROWSER_SCOPES["firefox"]` stays `(STATIC_ASSETS,)`, so the new group never runs there. State this in the module docstrings and in the commit body of Task 3.
- **AA, not AAA, for new pairings:** 4.5:1 text, 3:1 non-text. axe runs with exactly the tags `wcag2a`, `wcag2aa`, `wcag21aa`, `wcag22aa`. The axe check prints the minimum and maximum contrast ratio axe computed (passes and violations) on each run, and lowers no existing 7:1 gate. Existing checks and thresholds are not edited.
- **Contrast axe cannot compute** (text over a gradient or an image; axe `incomplete` message keys `bgGradient`, `bgImage`, `imgNode`) is printed as a `WARN` line and never fails and never vanishes. The bespoke contrast checks stay the owner of those pairings.
- **Dev-only.** Nothing is added to `requirements.txt`, `requirements-dev.txt`, the Dockerfile or `fly.toml`. The Dockerfile's `COPY . .` would ship the vendored file (about 640 KB, never imported by the app); Controller step 3 keeps it out with a `.dockerignore` line.
- **Tailwind scan:** no daisyUI word in any `static/js` comment. No file under `static/js`, `static/css` or `templates/` is edited except for the temporary RED defects below, which are reverted before staging.
- **Gate module rules (existing):** a gate module imports `scrobblescope` only below the facade's environment bootstrap, so no new module is imported by `frontend_gate.py` above line 63. A `check_*` function defined in a gate module must be registered once in `CHECKS` (`test_every_check_in_every_gate_module_is_registered_once`). Tests patch only the module they cover.
- **Tests that reach `main`:** the real gate tests (`tests/scripts/dev/test_frontend_gate.py`, `test_main_runs_and_closes_both_engines_with_named_failures` and its sibling) patch `frontend_gate._load_playwright` (returning `lambda: nullcontext(Mock())`, with `from contextlib import nullcontext` imported inside the test), `serve_app`, `_launch_browser` and `run_checks`. Every new test that calls `main` follows that pattern; the file's docstring says "Every test here is unit level and starts no browser", and none may start the real Playwright driver.
- **Lean tests:** one test per intended behaviour; none that pins wording; assertions use names long enough not to match by accident (`save-button`, not `a`). Pure decisions are unit-tested with fakes; browser behaviour is proven by a RED/GREEN run of the real gate with `--only`.
- **Commit format:** Conventional Commits, imperative, subject at most 72 characters, body explains why, wrapped at 72 (`AGENTS.md` Commit Rules). The worktree guard reports WT003 for the branch name `feat/live-a11y-gate`: advisory, accepted by the owner.
- **Browser runs** go through `C:/ssw/tools/with_browser_lock.py` with the interpreter's absolute path `C:/Program Files/Python313/python.exe` (one browser gate at a time on this machine).
- **Frozen names (manifest, `--only`, log):** checks `axe wcag 2.2 aa`, `keyboard tab-through`, `page motion navigation`; group `LIVE_ACCESSIBILITY = "live accessibility & navigation"`.
- **Out of scope:** any existing check or threshold, `requirements*.txt`, the Fly image, Firefox coverage, fixing the app's own violations.

## Decisions

**How axe-core is obtained: a vendored file, `scripts/dev/vendor/axe-core/axe.min.js`, version 4.14.0, SHA-256 `20c09fe157a8a34a30e241aaa1fcdade657734f08ab379ecfbeb7d45cc46e878`, 652140 bytes** (measured 2026-10-27 from `https://cdn.jsdelivr.net/npm/axe-core@4.14.0/axe.min.js`; npm `latest` was 4.14.0; header `/*! axe v4.14.0`; LF only; no private-key string, so `detect-private-key` passes; licence MPL-2.0). No pre-commit hook, Tailwind source, docsync rule or `.dockerignore` entry objects to the file (verified); Codacy and the Docker context are Controller steps 3 and 4.

| Option | Fly image | CI cache | Licence | Verdict |
|---|---|---|---|---|
| Vendored file, hash pinned in code | Kept out by a `.dockerignore` line | No new install step, no new cache key; works offline and on a first local run | MPL-2.0 is file-level: an unmodified file keeps its header notice, and `LICENSE` sits beside it | **Chosen** |
| PyPI wheel (an axe wrapper package) | None | Adds a pin to `requirements-dev.txt`, which changes `hashFiles('requirements-dev.txt')` and cold-starts the Playwright apt cache once; adds a third-party package to the pip-audit surface | Same file inside the wheel | Rejected: more moving parts for the same bytes, and the bundled axe version is the wrapper's choice, not ours |
| Download at run time, SHA-256 verified, cached like `scripts/bin` for Tailwind | None | A cache step and a download on first run | Same | Not chosen: it pins the same bytes, but needs the network on a first or offline run and a cache key; the vendored file needs neither |

The check refuses to run if the file's SHA-256 differs from the constant, so an edited or CRLF-converted copy fails loudly. `core.autocrlf=true` is set on this machine, so `.gitattributes` gets `scripts/dev/vendor/axe-core/* -text`.

**Bumping axe later** (the refusal text must say this, not "do not edit the pin"): add the new file, update `AXE_SHA256` and `AXE_VERSION` in one commit, re-run the check; rules that axe added or changed arrive as new failures and removed ones as stale entries. A bump commit is the one place the owner may re-derive the baseline and `BASELINE_MAX`.

**How known violations are handled:** `config/axe_baseline.toml`, one `[[known]]` table per violation (rule, state, target, theme, profile, finding, reason) and a `ceiling` equal to the entry count. The check fails on (a) any violation not in the baseline, (b) any baseline entry that no longer occurs ("remove it: the fix shipped"), (c) more entries than `ceiling`, and (d) a `ceiling` above `BASELINE_MAX`, a constant in the Python module that Task 4 sets to the measured count and that a unit test pins. Growing the baseline therefore touches the file, the constant and a test in one reviewed diff; **review, not tooling, is the control** (an author can still edit all three). There is no skip list and no `disabled` rule. Each entry cites a FINDINGS id. A baseline key includes the theme: a light entry never silences a dark violation on the same selector.

**Profiles and themes:** axe and keyboard run at desktop (1280x720) and mobile (390x844). The wide-touch profile (1280x800) renders the desktop layout and is covered by the touch-target check; adding it would double the time for no new layout. Axe runs in both themes (`data-theme` `light` and `dark`) per state; keyboard in light only.

**Pages and states** (one list, owned by Task 2): every path in `MIGRATED_PAGES` in the states `TOUCH_TARGET_STATES` already defines for `/` (as loaded, heatmap mode, decade filter, release year, thresholds open), plus the three populated pages the bare paths cannot show: `/results?job_id=` with albums, `/unmatched?job_id=` with rows, `/heatmap?job_id=` with a year of days. State labels are stable across runs: `serve_app` appends `/loading?job_id=<uuid>` to `MIGRATED_PAGES` (`scripts/dev/_frontend_gate_runtime.py`, ~line 126), so a label is built from the path without its query (`/loading`); no label, baseline entry or log line holds a random value.

**Known limits, stated plainly:** (1) Chromium only. (2) axe covers roughly the machine-checkable third of WCAG; it is not a substitute for a screen-reader pass. (3) Playwright's Chromium launches with the back/forward cache disabled, so the `pageshow` restore is exercised by dispatching a `pageshow` event with `persisted: true` after a real Back, and the check's docstring says so. (4) "Sane order" means DOM order equals Tab order and no `tabindex` above 0; a CSS reordering that diverges visually from the DOM is not detected. (5) The keyboard check tabs only states reached by a fresh navigation (Task 5); states that need a click first (heatmap mode, decade filter, release year, thresholds open) are scanned by axe but not tabbed.

### Task 1: `--only` for local single-check runs

**Wave:** 1. **Touches:** `scripts/dev/frontend_gate.py`, `tests/scripts/dev/test_frontend_gate.py`. **After:** none. **Mode:** serial.

**Behaviour.** `frontend_gate.py --only NAME` (repeatable) runs just the named checks, on Chromium only, so a task can prove one check RED then GREEN in seconds. A name that is not an enabled check (unknown, or listed in the manifest's `disabled`) stops the gate with the name on stderr before a browser launches. CI never passes `--only`. The normal summary line is not printed under `--only`; a different one is, so a partial run can never be read as a full pass.

**Frozen interface:** `run_checks(new_page, base_url, group_order=None, only=frozenset())`; CLI `--only NAME`; success line `[frontend_gate] --only passed: NAME[, NAME]` (names sorted). The names are validated the way `_load_check_manifest` validates manifest names.

### Task 4: axe-core WCAG check with a shrink-only baseline

**Wave:** 3. **Touches:** `scripts/dev/_frontend_gate_axe.py` (new), `scripts/dev/vendor/axe-core/axe.min.js` and `LICENSE` (new), `config/axe_baseline.toml` (new), `.gitattributes`, `tests/scripts/dev/test_frontend_gate_axe.py` (new), `scripts/dev/frontend_gate.py`. **After:** Tasks 2 and 3. **Mode:** serial. **Input from the controller:** `BASELINE_FINDING` (an `F-...` id) in CONTEXT.

**Behaviour.** For each `LiveState` and each theme, open the state, inject the pinned axe, run it with the four tags (the Impeccable Live overlay, `[id^="impeccable-live-"]`, excluded; result types violations, incomplete, passes), and judge. A violation not in the baseline fails; a baseline entry for this profile that no longer occurs fails; contrast axe could not compute prints one `WARN` line per run (stderr); one more line per run prints the minimum and maximum ratio axe computed and the count. Runs at desktop and mobile; the profile is read from the viewport (desktop at width 860 and above). Fail-closed: a missing or edited axe file, a bad baseline, or a baseline over its ceiling raises `FrontendGateError`, which the gate reports as a failed check. **Vacuous-pass guard:** a run that computed no contrast ratio at all fails (every page has text).

**Frozen interfaces:**

```python
AXE_VERSION = "4.14.0"
AXE_SHA256 = "20c09fe157a8a34a30e241aaa1fcdade657734f08ab379ecfbeb7d45cc46e878"
AXE_TAGS = ("wcag2a", "wcag2aa", "wcag21aa", "wcag22aa")
BASELINE_MAX = <the measured entry count, set in Step 6>
Key = tuple[str, str, str, str]   # (rule id, state label, target, theme)

@dataclass(frozen=True)
class KnownViolation:             # rule, state, target, theme, profile, finding, reason
def load_axe_source(path=AXE_PATH, sha256=AXE_SHA256) -> str          # FrontendGateError on mismatch
def load_axe_baseline(path=AXE_BASELINE_PATH) -> list[KnownViolation] # FrontendGateError on a bad file
def axe_failures(found: dict[Key, str], known: list[KnownViolation], profile: str) -> list[str]
def check_axe_wcag_aa(page, base_url) -> list[str]
```

`found` maps each key to its axe impact; messages name rule, state, target and theme. The loader rejects: a missing field, a non-integer or missing `ceiling` (a `FrontendGateError`, never a bare `TypeError`), more entries than `ceiling`, a `ceiling` above `BASELINE_MAX`, a profile other than desktop or mobile, a theme other than light or dark, a `finding` not matching `^F-[A-Z0-9]+-\d+$`, a `reason` under 20 characters. Targets use axe's selector (`>>` joins frames).

**Baseline file format (`config/axe_baseline.toml`)**, written in Step 6 from the measured run; the committed file has no sample entry:

```toml
ceiling = 0          # equals the number of [[known]] tables, never above BASELINE_MAX
[[known]]
rule = "color-contrast"
state = "/results as loaded"
target = ".album-card__meta"
theme = "light"      # light or dark
profile = "desktop"  # desktop or mobile
finding = "F-XXXX-0"
reason = "at least 20 characters saying why this is accepted for now"
```

**Acceptance (unit tests, fakes only):**
- A violation absent from the baseline fails naming rule, state, target and theme.
- A baselined violation passes; a baseline entry that no longer occurs fails and says to remove it; an entry for the other profile is not stale here.
- **A light-theme entry does not silence the same rule and selector found in the dark theme** (and the reverse).
- `load_axe_source` raises `FrontendGateError` for a file whose digest differs; the committed file matches the pin and starts with `/*! axe v4.14.0`.

### Task 5: Generic keyboard tab-through

**Wave:** 4. **Touches:** `scripts/dev/_frontend_gate_keyboard.py` (new), `tests/scripts/dev/test_frontend_gate_keyboard.py` (new), `scripts/dev/frontend_gate.py`. **After:** Tasks 2 and 4. **Mode:** serial.

**Behaviour.** For each `LiveState` that needs **no click** (empty `actions`; light theme), reach it by a fresh navigation and press the real Tab key with no click and no `blur()` before the first press, until focus leaves the page, returns to the first element, or the press budget (`2 * tabbable + 10`) runs out. A fresh navigation is the only reset (a click or an unproven `blur()` leaves Chromium's sequential-focus start point mid-document). States that need a click first are not tabbed (Decisions, limit 5). Judge:
- **Start guard:** the first Tab lands on the first element of `tabbable`; if not, the state fails with that message (this is the proof that the start point is known, on every state).
- every tabbable element was reached (a radio group counts once, as the browser tabs it; elements inside `[inert]`, disabled, hidden or the Impeccable overlay are not tabbable);
- every focused element changed at least one of outline, box-shadow, border, background, colour, text decoration or transform on itself, its label or its parent compared with its style before any focus (a visually hidden input is judged through its label);
- Tab never stayed on one element and the budget was not exhausted (a keyboard trap);
- the order is DOM order and no element has `tabindex` above 0.

**Vacuous-pass guard:** a state whose `tabbable` is empty, or whose traversal visits no step, fails (every page has the header links). Runs at desktop and mobile; spotlight is stubbed with `spotlight_stubbed`.

**Frozen interfaces:**

```python

def check_keyboard_tab_through(page, base_url) -> list[str]
```

`tabbable` is the names of the elements Tab should reach, in DOM order, as `tag#id` or `tag.firstclass`. Each `step` is `{"index": int, "name": str, "indicated": bool, "positive": bool}`. `ended` is one of `"left"`, `"wrapped"`, `"stuck"`, `"budget"`. Failure messages contain `no visible focus indicator on <name>`, `keyboard trap`, `<name> is not reachable by Tab`, `Tab order differs from DOM order`, `tabindex above 0`, and the start-guard message.

## Rollback

Each task is one commit, so a revert is `git revert` of that commit. To switch the three checks off without reverting code: move the names from `required` to `disabled` in `config/frontend_gate_checks.toml` (the manifest refuses a name that is in both, so remove it from `required` in the same edit); the header then prints them under `disabled:`. To remove the vendored axe file: revert Task 4 (and the `.dockerignore` and `.codacy.yml` lines); nothing else imports it. The workflow `-v` flip reverts independently (`-v` back to `-q`). Nothing touches `requirements.txt`, the Dockerfile or `fly.toml`, so there is no deploy rollback.
